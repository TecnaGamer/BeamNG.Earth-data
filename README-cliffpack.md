# cliffpack: the optional 4K cliff texture pack on the tile host

BeamNG.Earth PR #1412 (dynamic cliffs) can download a 4K cliff texture set. It is opt-in: cliffs on and 4K textures
selected. Anything wrong, and the game uses its bundled textures. This workflow publishes the pack to R2, behind
`https://tiles.tgforever.net`:

```
cliff/4k/<version>/<set>/<name>.webp    the 27 textures the app allowlists (immutable)
cliff/4k/<version>/ATTRIBUTION.md       the contributor's notices bundled (not listed in the manifest)
cliff/4k/<version>/manifest.json        {"format": 1, "files": [{"path", "size", "sha256"}, ...]}, uploaded last
```

Players' apps only read the pack once `cdn.json` has `"cliffs": {"enabled": true, "base": ".../cliff/4k/v1/"}`.
You add that key by hand, last. Old versions stay. The workflow never deletes anything. If a version's
`manifest.json` is already in the bucket, it is compared, never rewritten: a change needs a new version.

## Files

| File | What it is |
| --- | --- |
| `tools/cliffpack_ci.py` | Standard library only. Unzip, check, recheck, the bucket listing check, the live check, and the cdn.json edit. |
| `tools/cliffpack_pins.json` | Per version: the release asset's name, the zip's SHA-256 and the generated manifest's SHA-256. |
| `.github/workflows/cliffpack.yml` | Runs by hand only. Inputs: `version`, `tag`, `sha256`, `dry_run` (default true). |

## What each job checks

- **check** (no secrets):
  - Downloads the zip from this repo's release `cliff-4k-<version>`.
  - Checks its SHA-256 against the pin (and against the `sha256` input, if you give one).
  - Unpacks it with Python's `zipfile`. It refuses any name not on the allowlist, absolute paths, `..`, backslashes,
    symlink or special entries, duplicates (case-insensitive), encrypted or oddly compressed entries, and oversize
    entries. Files are created exclusively.
  - Checks the unpacked folder:
    - exactly the allowed files, with no symlinks, special files, other names or other folders;
    - all 27 WebPs: 26 B to 64 MiB each, at most 512 MiB in total;
    - each WebP's RIFF structure: the chunk sizes add up to the file exactly, one still image (no animation), and
      the sides are powers of two up to 4096 (the app's own Pillow check);
    - all 5 notices, UTF-8, and the four texture-set notices state CC0;
    - the handoff's `inventory.json` (size, SHA-256, dimensions) and its proposed `manifest.json` match the files
      exactly.
  - Generates `manifest.json` and `ATTRIBUTION.md`, and checks the manifest's SHA-256 against the pin.
  - Uploads the staged folder as an artifact. Nothing from the zip is ever executed.
- **publish** (R2 secrets; runs only this repo's checker and aws-cli; only from main, only when `dry_run` is false):
  - Rechecks the artifact: the exact file set, every WebP, the manifest regenerated byte-identical, and its
    SHA-256 equal to the pin.
  - Lists `cliff/4k/<version>/` and refuses any keys outside the pack. If the version is already published, it
    compares the manifest and stops.
  - Uploads the 27 WebPs (`image/webp`, `public, max-age=31536000, immutable`), then `ATTRIBUTION.md`.
  - Lists again and checks every file's size.
  - Uploads `manifest.json` last (`application/json`, `max-age=86400`).
- **live** (no secrets): fetches `manifest.json` and every file through the CDN and compares them byte for byte with
  the artifact. The job summary then prints the cdn.json command.

## Steps

The handoff zip is checked (`dc608142…cfdaea`, 35 entries), at
`~/bnge-tests/cliffpack/download-1795475638/cliff-4k-v1-handoff.zip`.

1. Copy the three files into the data repo (`tools/cliffpack_ci.py`, `tools/cliffpack_pins.json`,
   `.github/workflows/cliffpack.yml`). Commit and push to main.
2. Create the release and upload the zip:

   ```sh
   gh release create cliff-4k-v1 -R TecnaGamer/BeamNG.Earth-data --latest=false \
     --title "Cliff 4K pack v1 (handoff, PR #1412)" \
     --notes "Transfer archive for the cliffpack workflow; players never download it. SHA-256 dc608142b3389273f31d8c3a0b04005124472b0da2a3f33cf38db65b29cfdaea"
   gh release upload cliff-4k-v1 -R TecnaGamer/BeamNG.Earth-data \
     ~/bnge-tests/cliffpack/download-1795475638/cliff-4k-v1-handoff.zip
   ```

3. Do a dry run (check job only) and read its summary:

   ```sh
   gh workflow run cliffpack.yml -R TecnaGamer/BeamNG.Earth-data --ref main -f version=v1
   gh run watch -R TecnaGamer/BeamNG.Earth-data "$(gh run list -R TecnaGamer/BeamNG.Earth-data -w cliffpack.yml -L 1 --json databaseId --jq '.[0].databaseId')"
   ```

4. Publish:

   ```sh
   gh workflow run cliffpack.yml -R TecnaGamer/BeamNG.Earth-data --ref main -f version=v1 -f dry_run=false \
     -f sha256=dc608142b3389273f31d8c3a0b04005124472b0da2a3f33cf38db65b29cfdaea
   ```

   Wait for the **live** job to pass. Before you flip the key, you can test it in game with
   `BNE_CLIFFS_PACK_URL=https://tiles.tgforever.net/cliff/4k/v1/` (cliffs on, 4K selected).
5. Add the cdn.json key last, in a clone of the data repo on a fresh main. The script makes the minimal edit: every
   other key stays byte-identical, and it refuses any base other than `https://tiles.tgforever.net/cliff/4k/v<N>/`.

   ```sh
   git pull --ff-only
   python3 tools/cliffpack_ci.py cdn-key cdn.json --base https://tiles.tgforever.net/cliff/4k/v1/
   git diff -- cdn.json          # should equal cdn.json.diff (staged next to this README)
   git commit -m "cdn.json: the 4K cliff pack v1 (cliffs on; files and manifest live on tiles.tgforever.net, checked by the cliffpack workflow)" -- cdn.json
   git push
   ```

   Apps read cdn.json at most once an hour (`SWITCH_TTL_S`). Only builds that include PR #1412 read the key.

## Turning it off, and new versions

- **Off:** set `"enabled": false` in the `cliffs` key, or remove the key. The apps fall back to their bundled
  textures. Leave the files in place.
- **New version (v2):**
  1. Upload the new zip to release `cliff-4k-v2`.
  2. Add `"v2": {"asset", "zip_sha256"}` to `tools/cliffpack_pins.json`.
  3. Do a dry run: its summary prints the generated manifest's SHA-256. You can also run
     `cliffpack_ci.py unzip` and `check` locally.
  4. Pin that value as `manifest_sha256`, then publish v2.
  5. Run `cdn-key` with `.../cliff/4k/v2/`. v1 stays for older apps.
- **New texture names:** a name the app does not allowlist makes it reject the whole manifest. So the app change
  ships first; then update `EXPECTED` in `cliffpack_ci.py` and publish a new version.
